# ex04 · Giải thích từng dòng

| # | Biểu thức | Kết quả | Vì sao |
|---|---|---|---|
| 1 | `[] + []` | `''` | `+` với object → gọi `toString()`: `[]` thành `''`, `'' + ''` = `''` |
| 2 | `[] == false` | `true` | `false` → 0; `[]` → `''` → 0; `0 == 0` |
| 3 | `null == 0` | `false` | Trong `==`, `null` chỉ bằng `undefined` (và chính nó), không bị ép sang số |
| 4 | `null >= 0` | `true` | Phép so sánh `>=` lại ép `null` → 0. Không nhất quán với dòng 3 — lý do nên dùng `===` |
| 5 | `'5' * '2'` | `10` | `*` luôn ép về số |
| 6 | `'5' + 2` | `'52'` | `+` có một vế chuỗi → nối chuỗi |
| 7 | `NaN === NaN` | `false` | NaN không bằng chính nó → dùng `Number.isNaN` |
| 8 | `0.1 + 0.2 === 0.3` | `false` | float nhị phân: `0.30000000000000004` |
| 9 | `typeof NaN` | `'number'` | NaN là một giá trị của kiểu number |
| 10 | `!!'false'` | `true` | Chuỗi khác rỗng luôn truthy |

Bài học: trong code thật, đừng dựa vào các luật này — dùng `===`, ép kiểu tường minh (`Number(x)`, `String(x)`), và validate input.
